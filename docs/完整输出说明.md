# 输出与复现

当前用户输出约定见 [README 的固定输出结构](../README.md#固定输出结构)。输入目录旁只创建 `报销材料` 与 `核对清单`。报销材料根目录放 Word/PDF、审查表、新闻稿、签领表和情况说明；重命名后的发票、订单、行程单等有编号附件放在唯一的 `原始材料` 子目录。核对清单内只放同名 xlsx 与 json。

## 复现当前流程

```powershell
python main.py scan "D:\报销\本次材料"
# 打开 D:\报销\核对清单\核对清单.xlsx，核对并确认相关行，保存关闭
python main.py build "D:\报销\核对清单\核对清单.xlsx" --details "D:\报销\details.json"
```

不需要再次传 --review。核对表固定八列：原发票完整名称、问题、文字识别结果、处理建议、类型、名称、金额、校验标志位。类型/名称/金额非空时覆盖、留空时沿用原识别；程序只使用已校验材料重新配对，生成文件并把来源、问题及文件摘要存入 JSON 的 report 字段。颜色、问题和建议会刷新，人工覆盖和校验状态保持。只更新旧表及链接可执行 `python main.py review "核对清单.json的完整路径"`；如原件已变动，应保存旧成果并重新扫描。

报销单命名为 `{连续编号}.{物品名称}_{金额}.docx/pdf`；其附件放在 `原始材料/` 内，命名为 `{相同编号}.{物品名称}-{金额}元-{材料类型}.{实际扩展名}`。审查表、新闻稿都用 00，签领表单独导出并接在报销单后，情况说明最后。未知和未配对材料不复制，原件链接保留在清单。

已有 format=3 的核对清单可直接继续 build，已记录且未经人工修改的旧平铺附件会自动迁入子目录。生成摘要同时覆盖根目录成果与嵌套附件，重新编号或改名时清理对应旧文件；人工新增文件保持原样。

## 旧样例说明

本机 tests/完整输出、tests/完整输出_处理记录 及私有 fixtures 是旧版测试产物，保留原样供对照。它们的目录结构和扫描状态格式不代表当前程序，也不直接用于新版 build。旧的人工 CSV 可在重新扫描后通过 --review 显式导入，要求 source 与当前扫描完全一致。

历史排版结果参考了人工核对与参考答案，不能记为纯自动识别准确率。当前验证范围见 [测试说明](测试说明.md)。
