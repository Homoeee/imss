# 开发说明

用户入口只有根目录 main.py。它处理参数、交互和默认人员信息，再调用 imss.workflow；不存在转发用的 cli.py 或 __main__.py。安装后的 imss 命令也指向 main:main。

## 职责和依赖

- core/models.py：数据类、金额规范化和文件名校验，无 OCR、Office 或表格依赖。
- core/candidates.py：在副本上计算候选，排除明确编号/金额冲突和已占用发票，按独立证据排序并保留竞争候选。身份基于参与原件路径和摘要。金额兜底填出的名称不能再次作为独立名称证据。
- recognition/layout.py：聚合视觉行、补缺字段、保存区域；明确冲突不通过坐标补全消除。Extraction 兼容二元素解包，额外提供 layout 属性，旧调用和旧状态仍可用。
- recognition/refine.py：仅在未读到金额且没有退款/冲突提示时，定位支付状态上方或行程费用区域进行数字 OCR。要求两位小数，结果必须人工确认，不按发票金额猜小数点。
- output/candidate_review.py：呈现候选，build 时重新计算并校验身份、展示内容、原件争用。与主表修改重叠时拒绝覆盖，确认后仍运行整组校验。
- core/matching.py：发票锚点、明确配对、金额建议与组内校验。返回 Bundle 列表及未配对材料；Material 的字段补全与问题列表允许就地更新，展示层使用副本避免污染状态。
- recognition/extract.py：按文件内容识别格式，读取 PDF/Word 或调用本地 OCR；PDFium 使用全局锁，图片 OCR 可并发。
- recognition/rules.py：清理正文、判断材料类型、编排字段提取及行程/快递归类，不利用原件文件名猜测用途或金额。
- recognition/fields.py：商品标签及价格/数量附近的标题、实付字段和账单支出、订单编号提取。订单和发票使用不同金额规则，规格、服务说明和发票表头不作为商品名。
- recognition/tables.py：人员表标题和采购清单识别、总额标签、金额列及待确认汇总；多项物品用清单标题概括，不将单项价格当整份总额。Word 提取按表格行保留制表符，坐标提取按表头横坐标补回空单元格；下半部局部 OCR 只接受带总额标签的清单金额，并要求核对。
- recognition/invoices.py：发票缺字标题与独立税务特征分类；通过红色横线定位表格合计栏及明细区域后局部 OCR。版式只定位，不按表格或文件名猜金额；金额必须保留货币符号及两位小数，逗号替代小数点须提示，局部字段始终需确认。品名星号后只有英文乱码的结果不自动采用。
- output/review.py：Excel/CSV 导入导出、按问题程度排序、确认字段应用，以及保留用户填写内容的诊断刷新。仅 confirmed 明确为1/是才更新识别字段，source 和行集合必须与扫描一致。
- output/documents.py：模板字段替换、图片区布局及签名插入，不决定材料配对。
- runtime/：只定位和运行 vendor 内组件，不回退系统安装，不联网下载。
- storage.py：JSON 原子替换、SHA-256 摘要、原件校验。
- workflow.py：编排扫描、核对、组装和发布。目录名称集中在 output/workspace.py。

`STANDALONE_SHEETS` 包含签领表、签到表，扫描诊断、候选、归档和生成统一排除其发票配对。人员表不提取物品/金额，按正文标题独立导出 PDF 到输出根目录；原 PDF 直接复制，其他格式沿用特殊材料导出路径。签名造成的平均 OCR 低置信度留作提示，不阻止保留原表；提取失败或不支持格式仍阻止导出。旧版签领表共享分组仍可读取，但不进入报销 Word。

`--details` 接收逐笔信息 JSON。`workflow._build_into` 按默认人员信息、逐组配置、发票号码配置的顺序合并字段；自动组同时支持旧内部键 `invoice:<完整摘要>` 与旧表展示的 `auto-<摘要前16位>`，展示键优先，手工分组则使用清单原值。姓名字段要求字符串：`passenger_name` 可通过入口常量或命令行提供统一默认，`passenger_name_2`、`passenger_name_3` 由逐组 JSON 补充。`output/documents.py` 只替换对应文字占位符，签字图片仍独立处理，不将姓名转成签名。

`scan`/`run` 在输入、模板和待处理文件校验后，调用 `reset_scan_directories` 删除并重建两个固定输出目录。删除前预检全部目标：最终绝对路径必须是输入同级的“报销材料”和“核对清单”，不能包含输入，不能含符号链接或 Windows 重解析点。嵌套旧文件同样清理；模板不可引用即将删除的目录。`build`/`recheck` 不调用此函数，继续核对时保留现有状态和成果。

## 扫描到生成的数据流

scan 先列出原件并发提取，再按摘要标记重复材料，完成配对诊断后写 format=3 的核对清单.json 与核对清单.xlsx。JSON 保存扫描结果，Excel 保存用户修改，两者职责不同。JSON 中的 report 字段保存最新生成报告，不再写单独处理报告或隐藏标记。

build 的用户入口是核对清单.xlsx，自动查找同目录的核对清单.json 读取原件关联、原始识别值和生成历史，再应用该 Excel 最新保存的覆盖项。另存的 Excel 必须使用传入的那一份，不能退回默认核对表；Excel 入口与不同的 --review 同时传入时拒绝执行，避免读取错误的修改。旧 JSON 入口保留兼容，同样读取 Excel。build 校验原件 SHA-256、应用核对表，重新分组并检查名称/金额/附件。在系统临时目录内组装材料，确认目标文件可替换后发布。重命名的编号附件位于“原始材料”子目录，生成文档与审查表、新闻稿等独立 PDF 位于输出根目录。生成报告 files 字段用正斜杠相对路径记录文件摘要，包含 `原始材料/文件名`，兼容旧版根目录记录；重跑只覆盖未被人工修改的旧成果，不收编人工新增文件。managed_path 校验相对路径、唯一子目录和链接边界，发布与清理均使用此入口。原件路径和摘要不因核对而变化。不要把展示诊断持久化回原始扫描字段，否则修正配对后旧警告可能继续阻塞生成。

金额兜底必须在明确配对全部结束后进行，且发票尚无购买记录/清单、金额相同、候选双向唯一、无明确编号冲突。建议名称来自发票，match_basis=amount_only，保留警告，不能因补出名称就清除问题。人工确认后 match_basis=reviewed，但必须继续检查结构性冲突。

## 修改入口与验证

`recheck` 先应用已有明确确认，重新读取其他材料，再逐字段保留尚未确认的手工编辑。新 Excel 固定八列，output/review.py 负责诊断，review_table.py 负责八列交互，legacy_review.py 仅负责旧 Excel/CSV/候选导入。人工覆盖始终留在 Excel，不写回 JSON 的原识别字段；build 每次清除旧分组，仅对已校验材料调用 core/rematching.py。旧候选只作导入兼容，不再生成第二工作表。重新识别不发布报销文件，JSON 内已有生成摘要保持有效。

坐标为左上角原点的归一化比例，文字 PDF 的 confidence 为 null。OCR 稀疏模式只在首轮文字不足/置信度低时重试一次，两轮择优而不拼接，防止金额重复。Word 的 page 是内嵌图片序号；图片是帧号；PDF 是实际页码。

新增票据版式：先在 tests/test_order_fields.py 或 tests/test_core.py 增加匿名正文样例，再修改 recognition/fields.py；类型判断改 recognition/rules.py。新增配对行为：在 tests/test_review_workflow.py 覆盖唯一、歧义、争用、冲突和人工确认后的闭环。更改清单列名：同时修改 COLUMNS 和读取映射，保留 source 唯一性、整表行集合及金额校验。修改模板：保留承诺原图，运行表单测试和真实 Office 测试。

实付字段必须合并比较全部候选，不能按标签正则顺序取第一个。多个金额冲突或实付字段读不清时留空，不降级选商品原价。只有应付款或行程页费用时保留提示，退款/未付款状态始终提示。OCR 把“¥49.34”读成“¥49 34”时可提出 49.34，但必须带缺小数点警告；不将“¥1 8 10”随意拼接为金额。任何提取问题都会阻止自动生成，核实后由用户明确确认。

订单中的20位交易号不是发票号：只有电子发票本身或明确的发票号码字段才进入 invoice_ids。订单截图里的“查看电子发票”链接也不应改变材料类型。增加启发式时同时写拒绝误识别的用例，不只验证字段覆盖率。

```powershell
python -m unittest discover -s tests -v
```

测试使用已有解释器与项目 vendor。没有真实组件或私有语料的环境会跳过对应检查；不能把跳过记为通过的实测。开发工具的参考答案只用于外部评测和受控排版，不进入识别流程。

八列人工覆盖包括类型、名称、金额，空值回退原识别值。校验状态在刷新和 recheck 中保持，初次无问题行默认已校验。Windows 链接使用原生绝对路径，不对中文、空格做 URI 编码；写出时检查文件存在且在输入根目录内。review 命令只更新工作簿，不 OCR、不改 JSON 或报销成果。
