# 使用说明

首次使用请按 [README](../README.md) 的“扫描 → Excel 核对 → build”流程操作。输出固定为输入同级的 `报销材料` 和 `核对清单`，不支持自定义目录名；没有 `--output` 或 `--records-output` 参数。

重命名后的发票、订单截图、行程单等附件放在 `报销材料/原始材料/`；生成的报销单 Word/PDF，以及审查表、新闻稿、签领表、签到表和情况说明 PDF 放在 `报销材料/` 根目录。输入原件保持不变；“原始材料”不带空格，不再创建其他附件子目录。

## 命令职责

| 命令 | 作用 |
| --- | --- |
| `python main.py` | 输入材料路径后先扫描，等待核对 |
| `scan 输入路径` | 生成核对清单.xlsx、核对清单.json；不生成报销文档 |
| `build 核对清单.xlsx` | 应用非空覆盖值，筛选已校验材料重新配对并生成 |
| `review 核对清单.json` | 只升级八列核对表、保留填写并修复原件链接，不重跑 OCR |
| `recheck 核对清单.json` | 重读待校验材料，保留已校验状态及手工覆盖项 |
| `run 输入路径` | 扫描后立即生成可确定的组；问题组等待修改清单后 build |
| `doctor` | 检查项目内 OCR、语言模型和 LibreOffice |
| `init-template 模板.docx` | 创建可编辑的通用多页模板 |
| `export-pdf 报销材料路径` | 为已有 Word 补导出同名 PDF，保留已有有效 PDF，并同步状态报告 |

各命令可加 `--help` 查看参数。`scan/run` 支持 `--config`、`--template`；`run/build` 还支持 `--review`、`--details`、`--skip-pdf`、`--start`、`--signature-image`、`--student-id`、`--phone`。build 直接传入修改并保存的 xlsx；另存的 xlsx 应与扫描记录放在同一目录，并将该 xlsx 路径传给 build。`--review` 仅用于 run 或旧 JSON 入口指定核对表，兼容旧 CSV。CSV 不支持颜色及诊断刷新。

## 怎样修改清单并正确生成

核对文件只有“核对清单”一个工作表、以下八列。问题优先排列：红色、橙色、黄色在前，绿色在后。前三行保留使用提示，第四行为列名。

| 列 | 内容与填写规则 |
| --- | --- |
| A 原发票完整名称 | 保留所有原始材料的完整相对名称（含后缀、子目录）；点击打开输入目录的原件，不要修改 |
| B 问题 | 当前识别、配对及生成问题，build 后重新计算 |
| C 文字识别结果 | 显示原识别类型、名称、金额及 OCR 原文；长文本可选中单元格，在 Excel 编辑栏展开查看 |
| D 处理建议 | 针对问题给出修改或补件建议 |
| E 类型 | 人工覆盖项，可从下拉框选择；留空使用原识别类型 |
| F 名称 | 人工覆盖项；留空使用原识别名称；审查表、新闻稿、签到/签领表等用此列覆盖活动标题 |
| G 金额 | 人工覆盖项；留空使用原识别金额；只填写数字，最多两位小数，分笔截图保留每笔实际金额 |
| H 校验标志位 | 下拉选择“已校验”或“待校验”；原识别及配对无问题默认已校验，有问题默认待校验 |

E、F、G 初始留空，原识别值可在 C 列查看。填写任何一项只覆盖对应字段，其他留空字段仍使用原识别值。删除之前填写的覆盖内容后，再次 build 会恢复使用 JSON 中的原识别结果，而不会沿用上一次的人工值。

逐份点击 A 列核对原件，按需填写 E、F、G，核实后将 H 列选为“已校验”。同一笔支出的发票及相关附件都需要已校验。默认已校验的正常材料也可改为待校验，暂不参与生成。不要修改 A 列、列名，或删除原件数据行。

保存并关闭 Excel 后执行：

```powershell
python main.py build "D:\报销\核对清单\核对清单.xlsx"
```

build 每次都读取传入 Excel 最新保存的内容，应用本表非空覆盖值；空白字段沿用程序保存的原识别值。只使用当前“已校验”的材料，清除旧人工分组后重新配对。不沿用上一次的配对结果，也不要求填写分组或另一个候选表。唯一同名发票的多笔支付金额之和相符且没有明确编号冲突时，可自动组装分笔附件。用户只需修改 Excel；同目录的核对清单.json 由程序自动维护，用于关联原件和保存原始识别数据，需保留但无需编辑。旧 JSON 入口仍兼容，也会读取 Excel 的修改。

“已校验”表示用户已核对字段，仍需满足一张发票、购买记录或购买清单、金额一致及行程单完整等要求。金额冲突、多张相同候选、缺件或不能读取的文件仍不生成；具体问题与处理建议会回写 B、D 列，E、F、G 和 H 的用户输入保留。多个同名同金额发票不能凭空确定归属，需核对准确名称及原件编号依据。

修改清单后可重复执行 build，无需重新 OCR。改名或改为待校验后，程序清理上次生成但本次不再使用的文件；手工新增文件保留，人工修改过的旧成果仍阻止覆盖。原始识别 JSON 不会被人工覆盖值改写，原输入文件保持只读。

## 升级旧清单与原件链接

已有批次只需更新列和修复链接时，保存并关闭 Excel，执行：

```powershell
python main.py review "D:\报销\核对清单\核对清单.json"
```

该命令不重跑 OCR、不重建报销材料，保留已有人工字段修改和校验状态，把旧表升级为八列，重建全部原件链接。旧版 `1/是` 状态转换为已校验；没有人工改动且没有问题的行也按新规则默认已校验。旧分组不再作为新 build 的配对依据。旧 CSV/旧候选确认仍可读取，Excel 刷新后统一使用八列。

原件链接使用 Windows 本地绝对路径，直接指向输入原文件，中文和空格不做 URL 百分号编码，也不指向生成临时目录。refresh/build 都保留相同原件目标；原件不存在或越界时明确报错，不伪造一个打不开的链接。若原始输入目录被移动，需先恢复路径或重新扫描。

需要重新识别未校验材料并保留手工覆盖项时执行：

```powershell
python main.py recheck "D:\报销\核对清单\核对清单.json"
```

已校验原件保留原识别基线及 Excel 中的覆盖项，待校验原件重新 OCR；用户填写和校验状态均保留。新增或修改原始文件需重新扫描；scan/run 会清空重建两个固定输出目录，继续已有核对时使用 review、recheck 或 build。

当前仍使用项目内 Tesseract，新增坐标提取、稀疏版式重试和局部数字识别。局部识别只定位支付状态或行程费用附近，不能从整张图随便挑一个金额；结果附带核对提示，不自动通过。没有小数点的 `2170` 不会猜成 `21.70`。

PNG/JPG 发票与图片截图均按内容识别，不以扩展名决定是否发票；透明背景先合成白底。发票标题漏成“电子发”时，会综合税号、税率、价税合计等独立税务特征分类，订单中“查看电子发票”不构成发票证据。对于红色网格发票，可按横线定位价税合计和品名区域重读；局部 OCR 的金额或品名仍需确认。逗号被解释为小数点时单独提示，无小数点的整数串不会自动补点。类型已识别不表示品名、金额和配对已全部通过；低分辨率品名不清时，核对后补填，或使用原始 PDF/更清晰原图。

## 特殊情况

**签领表、签到表：** 根据正文开头的“某活动签到表”“某活动奖品签领表”等标题识别，标题分成活动名称和表名两行时合并。无需金额、物品名称或发票分组，直接按标题重命名后输出到“报销材料”根目录，不插入任何报销单，也不复制到“原始材料”。保留连续编号，排在各笔报销单之后、情况说明之前。PDF 原件直接复制，Word/图片与审查表一样导出独立 PDF，不重排原表内容。手写签名导致的平均 OCR 置信度提示仍显示在清单中，但不阻止原表导出；文件损坏或提取失败仍需处理。

如果标题没有识别出来，可在 Excel 的 E 列选择“签领表”或“签到表”，F 列“名称”填写完整活动表名，H 列选择“已校验”后 build。不要从文件名中的金额猜测表单内容。

**购买清单：** 支持采购/购买/销售/费用/餐费清单、采购明细表，以及有品名、数量、单价、金额和合计的表格。以清单标题概括整份明细，多项物品不会被当成错误；明确的“合计”“总计”“总额”“总金额”等字段用于提取总额。Word 保留行和单元格分隔，图片/PDF 的坐标用于对齐金额列，避免取到数量或单价。

合计栏为空或未读清时，只有金额列完整才提出按列汇总的建议；末尾独立金额没有总额标签时也需核查。长图片清单会对正文下半部做一次带中文标签的局部 OCR。上述汇总或局部识别均保留提示，需在 H 列明确选择已校验；金额冲突不会自动选取一个值。没有明确总额、表格金额列也不完整时，留空等待手工核对，不按文件名或发票金额反推。

购买清单作为发票的采购附件参与配对；核查其类型、名称和总额，将清单及对应发票都设为已校验后 build。必要时将对应附件的名称统一为准确的汇总名称。

- 同名物品买了两次：核查各笔名称、金额及原件编号；仍有多个完全相同候选时不任意配对，问题会保留在清单中。
- 分笔支付：同笔材料填写一致且准确的名称，每份截图保留各自实际金额并全部设为已校验；程序验证分笔之和等于发票总额，不要把每笔都改成发票总额。
- 多商品发票：在同一组统一填写真实汇总名称，金额仍为总额；不要把一张发票拆为多组重复报销。
- 共享签领表：设为已校验即可独立导出一份 PDF，无需分组，不插入报销 Word，也不要求金额。
- 重复原件：按 SHA-256 识别，只组装一次；有编号的附件副本仍可追溯来源。
- 类型未知：留在输入目录等待处理；改为“未知”不等于消除该待处理项。
- 不能识别或缺件：确认不能修复损坏文件或补出不存在的附件，需检查原件。

## 人员、用途和奖品状态

可修改 `main.py` 顶部的 `SIGNATURE_IMAGE`、`STUDENT_ID`、`PHONE`、`PASSENGER_NAME` 作为统一默认值，或在 build/run 使用 `--signature-image`、`--student-id`、`--phone`、`--passenger-name`。入口常量中的签字相对路径以项目目录为准，命令行路径以当前目录为准。

`detail.json` 是手工填写的逐笔补充信息，保存用途、乘车人、学号、签字图片等；`核对清单.json` 是程序保存的识别和生成状态。金额、配对、材料类型及确认状态仍在 Excel 核对清单修改。文件名 `detail.json`、`details.json` 都可以，以 `--details` 指定的实际路径为准；只把文件放在旁边不会自动读取。

使用步骤：

1. 将项目根目录的 `details.example.json` 复制成 `D:\报销\detail.json`，放在输入目录的上一级，与“报销材料”“核对清单”并列。不要放入这两个输出目录，重新 scan/run 会清空它们。
2. 从 A 列复制对应发票的完整原文件名称（包括子目录及后缀），替换示例的键；也可用真实发票号码，前导零要保留。旧 `auto-…` 配置键仍可使用，旧手工分组键请改为发票原文件名称或号码。
3. 每张发票写一个对象，只填写需要补充的字段，删除无关示例。同笔订单、行程单共用发票的配置，不需要每份附件写一遍。生成文件名前的 `01`、`02` 连续编号不能用作键。
4. 保存 JSON 和 Excel，关闭 Excel，再执行下方带 `--details` 的 build 命令。每次重建都要传入该参数，程序不会自动沿用上次的 details 文件。修改配置后重复同一条命令即可，无需重新扫描。

发票原文件名称对应字段覆盖统一默认值，发票号码对应字段优先级最高。实际使用时将以下键换成 A 列对应发票的原文件名称：

```json
{
  "车费发票.pdf": {
    "category": "行程",
    "purpose": "活动布置往返车费",
    "passenger_name": "张三",
    "passenger_name_2": "李四",
    "student_id": "SA12345678",
    "signature_image": "张三签字.png"
  },
  "打印纸发票.pdf": {
    "category": "物品",
    "purpose": "活动签到用纸",
    "student_id": "SA12345678",
    "phone": "13800000000",
    "signature_image": "签字.png",
    "is_prize": false,
    "amount_equal": true
  }
}
```

| 字段 | 用途 |
| --- | --- |
| `category` | 模板类别：物品、奖品、工作餐、行程、快递 |
| `purpose` | 购买或乘车事由；不提供时使用清单物品名称，`""` 则留空 |
| `passenger_name` | 行程表第 1 位乘车人姓名；填文字，不替代签字 |
| `passenger_name_2`、`passenger_name_3` | 第 2、3 位乘车人姓名；无同行人员可省略或留空 |
| `student_id` | 人员学号；行程模板填第 1 位乘车人的学号 |
| `phone` | 联系方式，填写到含电话栏的模板 |
| `signature_image` | 第 1 位乘车人或相应模板开票人签字图片路径；`""` 清除统一签名 |
| `invoice_number` | 覆盖表格中显示的发票号码，不更改配对依据；一般省略以沿用识别结果 |
| `is_prize`、`amount_equal` | 是否奖品、金额是否相符：填写 `true` 或 `false`，不提供则保持未勾选 |
| `actual_amount` | 表格内实际金额说明，例如 `"35.80"`；不改变配对校验、报销单编号或文件名中的金额 |
| `template` | 该组自定义 `.docx` 模板路径 |

所有姓名、学号、电话和图片路径均使用 JSON 字符串；学号、电话要加双引号，不能写成数字。JSON 不支持注释和末尾多余逗号。Windows 路径可写 `"D:/报销/张三签字.png"`，或将反斜杠写成 `\\`。

`signature_image` 和逐组 `template` 的相对路径以 details 文件所在目录为准；例如上述签字图片应放在 `D:\报销\张三签字.png`，没有图片就删除该字段或填 `""`。没有姓名、签字图片、学号和电话就留空。第 2、3 位乘车人的签名及学号栏保留供本人补填；程序保留模板中的承诺文字原图，不凭空生成签名。

```powershell
python main.py build "D:\报销\核对清单\核对清单.xlsx" --details "D:\报销\detail.json"
```

生成结果在 `D:\报销\报销材料`，检查对应的行程 Word/PDF。填写 detail.json 不会将待校验材料改为已校验，也不能绕过缺行程单、金额冲突等问题；这类问题需先在 Excel 中处理。

## 模板

内置模板位于 `imss/resources/templates/`，按类别选择，发票位于上方，订单/行程/运单等位于下方，下部表格填写用途和人员字段。单个图片区最多支持六页，超限报错；长截图会缩小，需检查可读性。

自定义通用多页模板：

```powershell
python main.py init-template "D:\报销\自定义模板.docx"
python main.py scan "D:\报销\本次材料" --template "D:\报销\自定义模板.docx"
```

文字字段支持 `{{sequence}}`、`{{item_name}}`、`{{amount}}`、`{{purpose}}`、`{{student_id}}`、`{{phone}}`、`{{passenger_name}}`、`{{passenger_name_2}}`、`{{passenger_name_3}}` 等。模板正文、表格、页眉页脚内的普通文字可替换，包括被 Word 拆分为多个 run 的占位符；文本框及域不保证支持。

图片区标记各自独占段落：`{{invoice_images}}`、`{{purchase_images}}`、`{{promise_images}}`，或只用 `{{all_materials}}`。不要混用、重复图片标记。图片位置应在正文或表格中，不支持页眉页脚、文本框；缺少某类标记时附件会追加在末尾。内置单页模板使用 `{{invoice_panel}}`、`{{evidence_panel}}`，与通用模板分开处理。签字图片可用 `{{signature_image}}` 定位。

## 运行设置与返回码

参考 `config.example.json`，用 `--config` 传入；未知配置项报错。Tesseract、tessdata 与 soffice 自定义路径仍必须位于项目 vendor 内，不使用系统组件。`office_backend` 为 `libreoffice`，旧值 `auto` 同样使用内置 LibreOffice。

`workers` 为 1–8，默认 2；`dpi` 默认 180。`max_pages`、`max_pixels` 限制输入页数和像素，超限报错；`ocr_timeout`、`office_timeout` 为每次组件调用的超时秒数，`ocr_min_chars` 控制 PDF 文字不足时是否补 OCR，也控制图片首轮文字过少时是否重试稀疏版式。

返回码 `0` 表示命令完成，`1` 为输入/配置错误，`2` 为仍有待处理项、导出失败或依赖检查未通过。scan 成功不等于所有字段无误；明确使用 `--skip-pdf` 不算生成失败。
