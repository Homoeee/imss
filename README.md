# 只能材料整理系统(Intelligent Material Sorting System, IMSS)

> 当前项目面向中科大先研院研会活动报销材料整理，暂不支持其他文件整理。

离线识别发票、订单截图、行程单及 Word 材料，按模板组合生成Word 和 PDF。

## 安装与检查

使用已有 Python 3.10+ 环境安装依赖：

```powershell
python -m pip install -r requirements.txt
python main.py doctor
```

## 如何使用

**1. 扫描原始材料。**

```powershell
python main.py scan "..\本次材料"   # 将所有报销材料放入同一文件夹，传入文件夹绝对路径
```

`scan` 和 `run` 会删除并重建输入同级的“报销材料”和“核对清单”，继续处理已有核对结果请执行 `build`；保留核对修改并重新识别请执行 `recheck`。

直接运行 `python main.py` 后输入材料路径，或在 `main.py` 顶部填写 `INPUT_DIR`，也会先扫描，等待核对。

**2. 打开 `..\核对清单\核对清单.xlsx`，核对并保存。**

核对文件只有八列：**原发票完整名称、问题、文字识别结果、处理建议、类型、名称、金额、校验标志位**。原文件名可点击打开输入原件，问题在前，正常材料在后。

“类型、名称、金额”是人工覆盖项，初始留空；不填使用 C 列展示的原识别值，填写则采用用户值，删除覆盖内容后恢复原识别值。H 列下拉选择“已校验／待校验”：原配对无问题默认已校验，有问题默认待校验。核查后修改必要字段并设为已校验；不要删除行或修改 A 列。

**3. 保存、关闭 Excel 后生成。**

```powershell
python main.py build "..\核对清单\核对清单.xlsx"
```

每次 build 都读取传入 Excel 中最新保存的修改，只使用当前全部已校验材料，应用覆盖值后重新配对，不沿用旧分组。缺件、金额冲突或多个相同候选仍会阻止相应组生成。修改后可重复 build；用户输入、原始识别基线和原件保留，问题和建议会刷新。用户只需修改 Excel；同目录的 `核对清单.json` 是程序自动维护的扫描记录，请保留，无需编辑。旧版传入 JSON 的命令仍兼容，也会读取 Excel 的修改。

已有批次只更新表格和链接、不重新 OCR：

```powershell
python main.py review "..\核对清单\核对清单.json"
```

重新识别待校验材料并保留手工覆盖项及状态：`python main.py recheck "..\核对清单\核对清单.json"`。review/recheck 不清空报销输出，旧表人工填写会迁入八列新表。

**4. 补充乘车人、用途等信息。** 将 [details.example.json](details.example.json) 复制成输出目录外的 `detail.json`，将示例键换成 A 列对应发票的原文件名称或真实发票号码，填写 `passenger_name`、`purpose`、`student_id` 等。每次生成时明确传入：

```powershell
python main.py build "..\核对清单\核对清单.xlsx" --details "..\detail.json"
```

所有字段见 [使用说明](docs/使用说明.md#人员用途和奖品状态)。

## 固定输出结构

```text
D:\报销\
├── 本次材料\                         # 原输入，只读保留
├── 报销材料\                         # 与输入同级，固定名称
│   ├── 原始材料\                     # 重命名后的报销附件
│   │   ├── 01.打印纸-35.80元-电子发票.pdf
│   │   └── 01.打印纸-35.80元-购买记录.jpg
│   ├── 00.某项目审查表.pdf
│   ├── 00.某活动新闻稿.pdf
│   ├── 01.打印纸_35.80.docx
│   ├── 01.打印纸_35.80.pdf
│   ├── 02.某活动签领表.pdf
│   └── 03.某活动签到表.pdf
└── 核对清单\                         # 与输入同级，固定名称
    ├── 核对清单.xlsx                  # 用户修改；诊断在 build 后刷新
    └── 核对清单.json                  # 扫描文字、原件摘要、设置及生成报告
```

输入旁固定创建“报销材料”和“核对清单”两个输出目录。报销材料内只增加“原始材料”一个子目录，放重命名后的发票、订单、行程单等附件；报销单 Word/PDF、审查表、新闻稿、签领表和情况说明放在报销材料根目录。不加批次、时间或输入名后缀。未配对材料保留在输入目录，通过清单链接查看。审查表、新闻稿用 `00`；报销单从 `01` 连续编号；签领表单独接在报销单之后，情况说明最后。同名附件加文件序号避免覆盖。

已有新版核对清单可直接继续 `build`，无需重新扫描。旧版平铺的附件若有生成摘要记录且未被人工修改，会在重建时迁入“原始材料”；人工新增或修改过的文件不会被自动迁移覆盖。

同一父目录再次执行 `scan` 或 `run` 时，旧的两个输出目录会清空重建。需要留存旧成果时先移走，或将新批次输入放在另一个父目录。已有扫描请用 `build` 继续，避免重新扫描清掉核对修改。输入无效、模板无效或输入内没有材料时，不清理已有输出；模板须放在输入目录或其他不会被清理的位置。文件被占用时关闭相关程序后重试。

## 常用选项

```powershell
# 明确配对的材料可一次扫描并生成；疑似配对仍等待确认
python main.py run "D:\报销\本次材料"

# 使用自己的模板、业务信息和统一开票人信息
python main.py build "D:\报销\核对清单\核对清单.xlsx" --template "D:\模板.docx" --details details.json --student-id "SA12345678" --phone "13800000000" --signature-image "D:\签字.png"

# 暂时只生成 Word；之后补导出 PDF
python main.py build "D:\报销\核对清单\核对清单.xlsx" --skip-pdf
python main.py export-pdf "D:\报销\报销材料"
```

统一签名、学号和联系方式也可在 `main.py` 顶部配置。逐笔用途、类别、奖品勾选和人员信息见 [详细使用说明](docs/使用说明.md)。未配置用途时“物品名称（用途）”使用清单物品名，真实用途可用 details 覆盖；其他未提供的人员及签字字段留空。

## 项目结构与二次开发

```text
main.py                        唯一入口：路径配置、参数、交互与环境检查
imss/
├── core/                      业务数据、配对和编号规则
│   ├── models.py              Material / Bundle / Settings 与金额校验
│   ├── matching.py            明确匹配 → 金额候选 → 完整性检查
│   ├── candidates.py          多证据候选排序与争用检查
│   └── numbering.py           连续编号
├── recognition/               文件提取与规则识别
│   ├── extract.py             文件头、PDF/Word/图片、OCR
│   ├── rules.py               类型判断、正文清理与识别编排
│   ├── fields.py              商品区域、实付金额与订单号提取
│   ├── layout.py              坐标视觉行、字段位置与证据
│   └── refine.py              支付/费用区域局部数字 OCR
├── output/                    Word 与 Excel 输出
│   ├── documents.py           模板填充、附件布局、签字图片
│   ├── review.py              彩色核对表、人工修改读取与诊断刷新
│   ├── candidate_review.py    候选工作表、批量确认与冲突检查
│   └── workspace.py           固定目录约定
├── runtime/                   本地组件定位与进程调用
│   ├── paths.py               vendor 定位和边界校验
│   └── office.py              LibreOffice 隔离转换
├── resources/templates/       五类单页模板与承诺图片
├── storage.py                 JSON、SHA-256 与原件校验
└── workflow.py                扫描与生成流程编排
tests/                         业务、核对闭环、输出与真实组件测试
tools/                         开发工具与离线评测，不参与用户入口
docs/                          使用、开发和测试说明
vendor/                        OCR、Office 及其许可证
```

不再保留 `cli.py` 或 `models` 混合业务包。关键函数写有职责、证据边界和处理原因的注释。新增字段版式先为 `recognition/fields.py` 增加匿名文本回归用例；类型判断在 `recognition/rules.py`；更改配对在 `core/matching.py`；更改清单在 `output/review.py`；更改模板布局在 `output/documents.py`。更详细的调用关系和修改约定见 [开发说明](docs/开发说明.md)。

订单识别现在按正文结构提取：没有“商品名称”标签时检查商品标题附近的价格和数量，排除店铺、规格及推荐商品。金额优先读取实际支付字段，明确标注的优惠不计为实付；多个实付值冲突时留空，只有应付款、行程页面费用或疑似缺小数点时保留核对提示。支付账单也支持顶部支出金额和换行的订单编号。

OCR 保留文字框、原始置信度和页码，按视觉行补全分散字段；首轮文字过少或置信度低时，增加一次稀疏版式识别并择优。金额漏读时按支付/费用标签定位区域做数字 OCR，补出的金额必须人工核查。当前仍使用本地 Tesseract，未更换为 PP-OCR。候选数不代表成功份数，真实准确率需另用人工标注评测。

这轮改的是字段提取逻辑，OCR 引擎仍为本地 Tesseract。已经漏读成空白或严重乱码的文字不能靠规则恢复；商品长标题与发票简称也可能需要在核对表中统一。新扫描自动采用新规则，已有核对清单不会被自动重算，`build` 继续使用清单中已保存、已确认的结果。

```powershell
python -m unittest discover -s tests -v
```
